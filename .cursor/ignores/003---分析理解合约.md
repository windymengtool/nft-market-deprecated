# 001---有几个核心合约

## 01---都有哪些合约

> 让我为您解释这几个合约的主要作用：
>
> 1. `EasySwapOrderBook.sol`：
> - 这是整个系统的核心合约，负责订单的创建、撮合和管理
> - 主要功能包括：
>   - 创建买卖订单（makeOrders）
>   - 取消订单（cancelOrders）
>   - 修改订单（editOrders）
>   - 订单撮合（matchOrder/matchOrders）
> - 管理交易费用和协议费用
> - 实现了可暂停功能，owner可以在紧急情况下暂停合约
>
> 2. `EasySwapVault.sol`：
> - 这是资产托管合约，负责存储和管理用户的NFT和ETH资产
> - 主要功能包括：
>   - 存入/提取ETH（depositETH/withdrawETH）
>   - 存入/提取NFT（depositNFT/withdrawNFT）
>   - 修改订单时的资产转移（editETH/editNFT）
> - 只允许OrderBook合约调用关键功能，确保资产安全
>
> 3. `OrderStorage.sol`：
> - 订单存储合约，负责订单数据的存储和管理
> - 使用红黑树实现了订单的价格排序
> - 主要功能包括：
>   - 添加订单（_addOrder）
>   - 删除订单（_removeOrder）
>   - 获取最优价格（getBestPrice）
>   - 查询订单列表（getOrders）
>   - 获取最优订单（getBestOrder）
>
> 4. `OrderValidator.sol`：
> - 订单验证合约，负责验证订单的有效性
> - 主要功能包括：
>   - 验证订单参数（_validateOrder）
>   - 管理订单的成交状态（filledAmount）
>   - 更新订单成交量（_updateFilledAmount）
>   - 取消订单（_cancelOrder）
>
> 5. `ProtocolManager.sol`：
> - 协议管理合约，负责管理协议费用
> - 主要功能：
>   - 设置协议费用比例（setProtocolShare）
>   - 确保协议费用不超过最大限制
>
> 这些合约共同构成了一个完整的NFT交易系统：
> - `EasySwapOrderBook`作为主合约，协调其他合约的工作
> - `EasySwapVault`负责资产安全
> - `OrderStorage`提供高效的订单存储和查询
> - `OrderValidator`确保订单的有效性
> - `ProtocolManager`管理平台的收费机制
>
> 整个系统实现了一个去中心化的NFT交易市场，支持固定价格交易，并确保了交易的安全性和效率。



## 02---都要部署吗

> 让我为您分析这些合约的部署关系：
>
> 不是所有合约都需要独立部署到链上。这些合约的部署关系如下：
>
> 1. 需要独立部署的合约：
> - `EasySwapOrderBook.sol`：主合约，需要部署
> - `EasySwapVault.sol`：资产托管合约，需要部署
>
> 2. 不需要独立部署的合约：
> - `OrderStorage.sol`：作为抽象合约被 `EasySwapOrderBook` 继承
> - `OrderValidator.sol`：作为抽象合约被 `EasySwapOrderBook` 继承
> - `ProtocolManager.sol`：作为抽象合约被 `EasySwapOrderBook` 继承
>
> 这一点可以从 `EasySwapOrderBook` 合约的继承关系看出：
>
> ```solidity
> contract EasySwapOrderBook is
>     IEasySwapOrderBook,
>     Initializable,
>     ContextUpgradeable,
>     OwnableUpgradeable,
>     ReentrancyGuardUpgradeable,
>     PausableUpgradeable,
>     OrderStorage,
>     ProtocolManager,
>     OrderValidator
> ```
>
> 部署流程应该是：
>
> 1. 首先部署 `EasySwapVault` 合约
> 2. 然后部署 `EasySwapOrderBook` 合约
> 3. 调用 `EasySwapVault.setOrderBook()` 设置 OrderBook 地址
> 4. 调用 `EasySwapOrderBook.setVault()` 设置 Vault 地址
>
> 其他三个合约（OrderStorage、OrderValidator、ProtocolManager）的代码会在部署 EasySwapOrderBook 时作为其一部分被一起部署，它们的功能会被整合到 EasySwapOrderBook 合约中。
>
> 这种设计模式的优点是：
> 1. 节省 gas 费用，减少部署成本
> 2. 通过继承实现代码的模块化和复用
> 3. 便于管理和维护，各个模块职责清晰
> 4. 减少跨合约调用，提高效率

> 根据对合约代码的分析，我来为您解释为什么部署时需要2个账号：
>
> 1. 主要合约架构：
> - `EasySwapOrderBook.sol`：主要的订单簿合约，负责处理订单的创建、撮合和取消等核心业务逻辑
> - `EasySwapVault.sol`：金库合约，负责存储和管理用户的NFT和ETH资产
>
> 2. 需要2个账号的原因：
>
> a) 部署顺序和所有权关系：
> - 第一个账号用于部署和拥有 `EasySwapVault` 合约
> - 第二个账号用于部署和拥有 `EasySwapOrderBook` 合约
>
> b) 安全考虑：
> - 这种设计实现了职责分离，增加了系统的安全性
> - Vault合约和OrderBook合约分别由不同的账号控制，降低了单点故障风险
>
> c) 合约交互关系：
> - Vault合约需要设置OrderBook的地址作为授权地址（通过`setOrderBook`函数）
> - OrderBook合约需要设置Vault的地址（通过初始化函数`initialize`）
> - 这种双向授权关系需要两个独立的账号来完成
>
> 3. 部署流程：
> ```
> 1. 账号A部署EasySwapVault合约
> 2. 账号B部署EasySwapOrderBook合约，并在初始化时设置Vault地址
> 3. 账号A调用Vault合约的setOrderBook函数，设置OrderBook地址
> ```
>
> 4. 关键代码证明：
>
> 在EasySwapVault中：
> ```solidity
> modifier onlyEasySwapOrderBook() {
>     require(msg.sender == orderBook, "HV: only EasySwap OrderBook");
>     _;
> }
> ```
>
> 在EasySwapOrderBook中：
> ```solidity
> function initialize(
>     uint128 newProtocolShare,
>     address newVault,
>     string memory EIP712Name,
>     string memory EIP712Version
> ) public initializer {
>     // ... 初始化时需要设置Vault地址
>     setVault(newVault);
> }
> ```
>
> 这种设计模式确保了：
> 1. 资产的安全性（通过Vault合约管理）
> 2. 业务逻辑的独立性（通过OrderBook合约处理）
> 3. 系统的可升级性（两个合约可以独立升级）
> 4. 权限的分散化（不同账号控制不同合约）
>
> 因此，使用两个账号进行部署是该系统架构设计的必然要求，这样可以实现更好的安全性和可维护性。
