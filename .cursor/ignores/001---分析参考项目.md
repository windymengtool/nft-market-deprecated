# 001---各个作用

根据搜索结果，我可以对各个参考项目的作用进行概括：

> 1. `nft-market-fe`: 基于Next.js的NFT市场前端项目，负责用户界面展示和交互。
>
> 2. `EasySwapContract`: NFT交易的智能合约项目，实现了基于订单簿模型的NFT交易系统，包括限价买卖、市价买卖等核心功能。
>
> 3. `EasySwapBackend`: NFT市场的后端API服务，提供用户登录、NFT集合管理、NFT物品管理、交易订单等接口服务。
>
> 4. `EasySwapSync`: 区块链事件同步服务，负责将链上的NFT交易事件同步到数据库中，保持链上数据与后端数据的一致性。
>
> 5. `EasySwapBase`: 基础工具库项目，为其他服务提供通用的工具函数、数据库操作、HTTP客户端、日志等基础功能支持。
>
> 这五个项目共同构成了一个完整的NFT交易市场系统，实现了从智能合约、后端服务到前端界面的全栈功能。

# 003---部署/学习顺序

> 根据项目的依赖关系和复杂度，我建议按照以下顺序部署和学习项目：
>
> 1. **第一步：部署基础设施**
>    - 配置MySQL数据库和Redis
>    ```bash
>    cd 参考资料/EasySwapSync
>    docker-compose -f docker-compose-arm64.yml up -d
>    ```
>    - 注册Infura账号，获取Sepolia测试网的API密钥
>
> 2. **第二步：部署智能合约 (EasySwapContract)**
>    - 这是整个系统的基础，其他服务都依赖于合约的部署
>    ```bash
>    cd 参考资料/EasySwapContract
>    npm install
>    cp .env.example .env
>    # 配置.env文件：
>    # - SEPOLIA_ALCHEMY_AK
>    # - SEPOLIA_PK_ONE
>    # - SEPOLIA_PK_TWO
>    npx hardhat compile
>    npx hardhat test
>    npx hardhat run --network sepolia scripts/deploy.js
>    ```
>    - 记录部署后得到的合约地址，后续需要配置到其他服务中
>
> 3. **第三步：部署基础库 (EasySwapBase)**
>    
>    - 这是其他Go服务的基础依赖，不需要部署
>    ```bash
>    cd 参考资料/EasySwapBase
>    go mod tidy
> ```
>    
> 4. **第四步：部署区块链同步服务 (EasySwapSync)**
>    - 负责同步链上数据到数据库
>    ```bash
>    cd 参考资料/EasySwapSync
>    cp config/config.toml.example config/config.toml
>    # 修改配置文件：
>    # - 数据库连接信息
>    # - Redis连接信息
>    # - 合约地址
>    go mod tidy
>    go run main.go daemon
>    ```
>
> 5. **第五步：部署后端API服务 (EasySwapBackend)**
>    - 提供前端需要的API接口
>    ```bash
>    cd 参考资料/EasySwapBackend
>    cp config/config.toml.example config/config.toml
>    # 修改配置文件：
>    # - 数据库连接信息
>    # - Redis连接信息
>    # - 合约地址
>    # - Infura API配置
>    go mod tidy
>    cd src
>    go run main.go
>    ```
>
> 6. **第六步：部署前端服务 (nft-market-fe)**
>    ```bash
>    cd 参考资料/nft-market-fe
>    pnpm install
>    # 配置环境变量，指向后端API地址
>    pnpm dev
>    ```
>
> 学习建议：
> 1. **基础知识学习**
>    - 以太坊基础概念
>    - NFT标准（ERC721/ERC1155）
>    - 智能合约开发
>    - Go语言基础
>    - React/Next.js基础
>
> 2. **项目学习顺序**
>    - 先研究`EasySwapContract`的合约代码，理解NFT交易的核心逻辑
>    - 学习`EasySwapBase`的工具库，了解与区块链交互的基础设施
>    - 研究`EasySwapSync`的同步机制，了解如何监听和处理链上事件
>    - 学习`EasySwapBackend`的API设计，理解后端服务的业务逻辑
>    - 最后学习`nft-market-fe`的前端实现，了解完整的用户交互流程
>
> 3. **重点关注**
>    - 订单簿模型的实现（合约层）
>    - 事件同步机制（同步服务）
>    - 数据模型设计（后端服务）
>    - API接口设计（后端服务）
>    - 用户交互流程（前端服务）
>
> 4. **调试技巧**
>    - 使用Hardhat进行合约调试
>    - 使用GoLand IDE调试Go服务
>    - 使用Chrome开发者工具调试前端
>    - 使用日志追踪问题
>
> 5. **注意事项**
>    - 确保每个服务的配置文件正确设置
>    - 注意服务之间的依赖关系
>    - 保持测试网络的ETH余额

>

## 01---不需要部署EasySwapBase

> 从提供的`EasySwapBackend`和`EasySwapSync`项目的`go.mod`文件中可以看出，这两个项目都引用了`EasySwapBase`模块：
>
> 1. **EasySwapBackend**:
>    - 在`require`部分中，明确引用了`github.com/ProjectsTask/EasySwapBase`，这表明`EasySwapBackend`项目依赖于`EasySwapBase`。
>
> 2. **EasySwapSync**:
>    - 同样在`require`部分中，引用了`github.com/ProjectsTask/EasySwapBase`，这表明`EasySwapSync`项目也依赖于`EasySwapBase`。
>
> 因此，`EasySwapBase`是作为库被其他项目引用的，而不是一个需要单独部署的独立项目。
